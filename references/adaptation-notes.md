# 方向适配速查（从现有 skill 抄录的答案）

> 用途：把台词系统落到具体方向时，按方向直接套这里的触发信号、素材分层与质量检查，不必重新调研。
> 来源：从既有的桌宠方向工程与角色卡方向的实践里抄录整理（那些工程的细节不在本仓，这里的结论自包含）。

## 桌宠方向（P0）

**触发信号清单**（直接进触发层与上下文层设计）：
- 状态机状态：idle 待机、互动中、提醒、拖拽
- 用户事件：左键、右键、拖拽、托盘菜单、全局打字响应（须授权）
- 定时：提醒窗

**互动维度设计**（进 M1 的维度取值）：
- 首版 2~4 个与角色匹配的互动，不机械套用。示例：猫 → 摸头/喂小鱼干/逗猫；狗 → 挠下巴/喂骨头/接球。
- 互动名即触发维度取值，一个互动一组格子台词。

**变体数参考**：
- 待机是最高频状态（源 skill 要求待机 ≥4 帧），台词侧对应：待机格子变体 ≥4 条；眨眼/反馈类（≥5 帧）可 2~3 条。高频状态台词不足会很快重复。

**文案要求**：提醒窗/面板用角色化文案（角色色板、圆角卡片、角色化措辞），台词系统产出的文案直接供这些 UI 消费。

**迭代节奏**：先 2~4 个互动 → 用户选择 → 局部迭代，不一次塞满全部功能。

## 角色卡方向（P1）

**台词去向映射**（台词系统产出 → 卡字段）：
| 台词系统产物 | 角色卡落点 |
| --- | --- |
| 格子台词（角色原话） | `first_mes` 开场、`description` 的 `<START>` 示例对话 |
| 硬规则（口癖/句式上限/禁止项） | `system_prompt` / `post_history_instructions`（精简，不塞满） |
| 台词风格锚点 | `depth_prompt` 的 Personality 标签（≤16 字短标签） |

**硬规则是约束，不是维度**：角色常有硬性说话规则（实例：句子 15 字上限、必须每句带口癖）。这类约束不进格子维度，进模板前缀或校验项——台词系统生成后须整体过一遍硬规则。

**台词素材分层（原句优先 → 模板兜底）**：
- 优先用角色原句（示例表 ✅ 列 → 设定文档引文 → 人设原句 → 外观原句 → 其余素材）。
- 原句不足时，只轻量编动作描写/衔接词，不编角色台词主体。
- 模板兜底是最后手段，兜底内容也要贴角色语气。

**空库分配法**（素材稀缺时的分配策略，卡萝案例：全卡可用原句仅 7 条）：
- 盘点可用原句总数 → 按「开场 3 条 + 每示例组 1 条」分配 → 保证互不重复 → 缺的用动作/衔接补。
- 对应台词系统：格子优先用原句，变体数按可用原句数定，宁可少写变体也不硬编。

**质量检查项**（从精修断言清单摘录，台词系统产出可借用的验收项）：
- 台词主体互不重复（角色卡侧：user/char 不同句）
- 无占位残留（【需补充】/【这里...】类）
- 硬规则逐条落实（漏硬规则是已记录的真实踩坑）
- 台词长度受 token 预算约束（角色卡侧有 token 统计）

## 给脚手架的三条关键启示

1. **素材分层**：原句（格子）优先 → 轻编（动作/衔接）→ 模板兜底，优先级不可颠倒。
2. **硬规则外置**：口癖/句式限制是生成后的校验项，不是触发维度。
3. **空库先盘点**：素材不足时先数可用原句再定变体数，不硬编台词凑格子。
